# 0xAF-Re Agent

0xAF-Re is a focused reverse engineering and CTF agent built from the core ideas in `oh-my-pi`:

- one Agent Loop,
- pluggable provider adapters,
- a single tool registry,
- append-only JSONL sessions,
- role-based routing between planner and executor models,
- interruptible turns, context compaction, tiered tool approval, session resume, and MCP tools.

It is intentionally much smaller than `oh-my-pi`; the first version is a practical lab tool rather than a full TUI framework.

## Default Routing

- **Planner:** `codex` uses local `codex exec` inside a tmux task for reverse analysis, exploitability reasoning, and solve planning.
- **Executor:** `claude` uses local `claude -p` inside a tmux task for lower-sensitivity execution, file inspection, and summarization.
- API fallback providers: `codex-api`, `claude-api`, `grok`, `deepseek`, `glm`, `mock`.

Every model is configurable in `agent.config.json`.

## Quick Start

```bash
cd 0xaf-re-agent
bun src/cli.ts --welcome
bun src/cli.ts --smoke
cp config.example.json agent.config.json
```

`--welcome` prints a guided first-run path with copy/paste demos. The bundled
demo workspace lives at `demos/welcome` and is safe to run locally:

```bash
bun src/cli.ts --workspace ./demos/welcome \
  -p "Triage this workspace. List files, identify the challenge, and propose a first solve plan."
```

Default Codex/Claude providers use your local CLIs and tmux. They do not read `OPENAI_API_KEY` or `ANTHROPIC_API_KEY` directly:

```bash
codex login status
claude auth status --text
```

The default CLI providers unset API-key env vars before launching the child CLI (`OPENAI_API_KEY` for Codex, `ANTHROPIC_API_KEY` for Claude) so a stale API key does not override local CLI login.

For API fallback providers, set the credentials you use:

```bash
export OPENAI_API_KEY=...
export ANTHROPIC_API_KEY=...
export XAI_API_KEY=...
export DEEPSEEK_API_KEY=...
export ZAI_API_KEY=...
```

Or let the tool guide and store a local credential:

```bash
bun src/cli.ts auth status
bun src/cli.ts auth login claude-api
bun src/cli.ts auth login codex-api
bun src/cli.ts auth login grok
```

Credential lookup order:

- current process env,
- `./.env`, `~/.0xaf-re-agent/.env`, `~/.omp/agent/.env`, `~/.env`,
- `~/.0xaf-re-agent/secrets.json` created by `auth login`.

Claude Code app login is separate from a raw Anthropic API key. If you want the standalone Claude Code CLI to use your subscription, run `claude auth login`. This agent's Anthropic adapter can use it only when a usable token is exported as `ANTHROPIC_API_KEY` or `ANTHROPIC_OAUTH_TOKEN`, or when you paste one with `auth login claude`.

Manual Claude API config in `agent.config.json`:

```json
{
  "providers": {
    "claude": {
      "type": "anthropic",
      "label": "Claude Code Opus 4.8",
      "model": "claude-opus-4-8",
      "baseUrl": "https://api.anthropic.com",
      "authScheme": "api-key",
      "apiKey": "sk-ant-api-..."
    }
  }
}
```

For an Anthropic OAuth/WIF bearer token, use:

```json
{
  "providers": {
    "claude": {
      "type": "anthropic",
      "label": "Claude OAuth",
      "model": "claude-opus-4-8",
      "baseUrl": "https://api.anthropic.com",
      "authScheme": "bearer",
      "apiKey": "YOUR_ANTHROPIC_OAUTH_TOKEN"
    }
  }
}
```

Prefer `ANTHROPIC_API_KEY` / `ANTHROPIC_OAUTH_TOKEN` or `auth login claude` over committing secrets to config. `agent.config.json` is gitignored in this project. `CLAUDE_CODE_OAUTH_TOKEN` generated by `claude setup-token` is for Claude Code CLI/Agent SDK flows; it is not the same thing as a standard Anthropic API key.

If `codex-api` returns `invalid_api_key`, the current `OPENAI_API_KEY` is present but not accepted by the OpenAI API. Replace it or remove it before trying a stored credential:

```bash
unset OPENAI_API_KEY
bun src/cli.ts auth logout codex-api
bun src/cli.ts auth login codex-api
```

For direct OpenAI Responses API calls, use an API key from the OpenAI Platform project that has access to the selected model. To bypass local Codex temporarily, switch the planner:

```bash
bun src/cli.ts --planner deepseek --workspace ./ctf
bun src/cli.ts --planner grok --workspace ./ctf
bun src/cli.ts --planner codex-api --workspace ./ctf
```

Run interactively:

```bash
bun src/cli.ts --workspace /path/to/ctf/workdir
```

Run one prompt:

```bash
bun src/cli.ts -p "Plan static triage for ./chall" --role planner
```

Force execution through Claude:

```bash
bun src/cli.ts --agent claude -p "Use local tools to inspect ./chall"
```

Use API Claude explicitly:

```bash
bun src/cli.ts --agent claude-api -p "Summarize this solve note"
```

Cross-check with Grok:

```bash
bun src/cli.ts --agent grok -p "Review this reverse engineering plan for blind spots"
```

Use your local Grok Build CLI login/config instead of the xAI API provider:

```bash
bun src/cli.ts --agent grok-cli -p "Review this reverse engineering plan for blind spots"
```

### Shell Escape

A line starting with `!` runs in the workspace shell instead of going to a model:

```text
!ls -la
!file ./chall && strings -n 8 ./chall | head
```

- Output streams to the terminal while the command runs; `^C` kills the command
  without leaving the REPL.
- The command, exit code, and (truncated) output are appended to the transcript,
  so the next prompt can refer to what you just ran.
- The same execution policy as `run_command` applies — destructive patterns are
  blocked, and network/sensitive commands need `--allow-network` /
  `--allow-sensitive`. Commands are also capped by the policy timeout (30s).

## Live Dashboard

Every turn draws itself inside one boxed dashboard. The dataflow strip and the
HUD are both on by default, and the box sheds the transient sections before
anything important when the terminal is short:

```text
╭─ ⠹ 0xAF·RE ──────────────────────────────────────────╮
│ codex → claude                  ▰▰▰▱▱▱▱▱ 40%  $0.71 │
│ FLOW  [you]═•═▶[ctx]▲═•═▶((deepseek))   ⣻ waiting     │
│ TOOLS  [tools]◀═•═[calls×1]   ⣾ run_command 5.6s     │
│ PLAN  1/5  ▰▰▱▱▱▱▱▱ 20%                               │
│   ✔ triage: file/arch/packer                  1.2s    │
│   ⠿ locate the check function                2m08s    │
│   ○ reproduce the flag path                           │
│ THINK  ┊ 校验函数看着像 sub_401a20，改之前先看 xrefs   │
│ TELE  out ▁▂▅█▆▃▂▁ 1.2k · think 105 · ◷ 4m12s         │
╰───────────────────────────────────────────────────────╯
```

- **FLOW** is a compact strip: `[you] → [ctx] → ((model))` with packets moving
  along the wires, nodes lighting up as they take part. The `▲` on the ctx end
  of the model wire marks tool results flowing back into the context that feeds
  the next request.
- **TOOLS** appears only when tools are in play: the return leg, the active
  tool with its running time, and a `✓/✗` tally.
- **PLAN** owns the whole task list — counts, progress bar, and every step,
  CJK included — so the strip stays diagram-only.
- **THINK** tails the streamed reasoning; **TELE** carries throughput,
  token counters, and the running clock.

On a short terminal the box drops FLOW/TOOLS first, then THINK, then TELE,
before folding the task list, so the step being worked on always stays visible.

**The trace** lands in the scrollback and stays there, stamped from the start of
the turn, so a finished run reads like a packet capture:

```text
t+ 0.005 ▏⇢ POST https://api.deepseek.com/v1/chat/completions
         ▏  model=deepseek-chat in=17 msgs=1 tools=23
t+ 3.680 ▏⇠ 200 out=103 cache=3.5k calls=2 ██████████ 3.7s
t+ 3.681 ▏ ⚙ file_info path=chall.js
t+ 3.692 ▏ ✓ 10ms $ file chall.js
t+ 3.696 ▏↻ turn 2
t+ 6.272 ▏⇠ 200 out=46 cache=3.5k ███████░░░ 2.6s
t+ 6.277 ▏■ turn complete via deepseek 6.3s
```

Plan updates appear as *transitions*, not dumps — `◇ plan 1/5 ✔ locate the check
function 8.2s`. A list still being written (one `TaskCreate` per step) stays
silent until something actually moves, and the full list is archived once, at the
end of a turn that touched it.


Duration bars share one scale per turn (the slowest request fills the bar), so
the shape of a turn is readable at a glance: where the time went, how many round
trips it took, which tool was slow.

```text
/flow full     dashboard + trace (default)
/flow flow     dashboard only
/flow trace    trace lines only
/flow off      neither — the plain tool tree comes back
```

The choice is saved to `~/.0xaf-re-agent/ui.json`; `--flow <mode>` overrides it
for one run. The strip hides itself below 46 columns and in non-TTY output; the
trace degrades to plain text without escape sequences.

## Task List

Multi-step work gets a visible task list. Two sources feed one tracker:

- the host `update_plan` tool, for the direct-API providers (deepseek, claude-api,
  codex-api, grok);
- the CLI providers' own native task tools — Claude Code's `TaskCreate`/`TaskUpdate`
  and codex's `plan_update` are parsed straight out of their JSONL streams.

The list survives across turns and across `--resume`, and it is shown in two
places: the PLAN section of the live dashboard, and `◇` transition lines in the
trace. `/plan` reprints it on demand.

## Interrupting A Turn

`^C` during a turn aborts it: the HTTP request is cancelled, a tmux CLI provider's
session is killed, and running tool subprocesses get the signal too. The REPL stays
open, and the partial work stays in the transcript — every tool call that was issued
still gets a result recorded, so the next turn (or a resumed session) is a valid
history for strict chat APIs.

## Context Budget

The full transcript is always on disk. What gets *sent* is trimmed to the provider's
`contextBudgetTokens` (default 48k, set per provider in `agent.config.json`), in two
mechanical passes: old tool-result bodies are elided first (their first line survives
as a pointer), then whole oldest exchanges are dropped behind a `[context compacted]`
marker. A tool call is never separated from its results.

```text
/context                    ≈12400 tokens of 48000 budget (25%) · 42 messages
/compact                    ask the model for a briefing and restart from it
/compact codex              use a specific provider for the summary
```

Large tool output never lands in context whole: anything over
`--max-output` (default 24000 chars) keeps head+tail and the full text is written to
`sessions/artifacts/`, with the path handed to the model so it can `read_file`/`grep`
the rest.

## Tool Approval

Two inputs decide whether a call runs: the tool's tier (`read` / `write` / `exec`)
and the session's mode.

| Mode | Auto-approves | Asks |
| --- | --- | --- |
| `yolo` | everything | nothing |
| `safe` (default) | every tier | commands tripping a safety pattern |
| `write` | read, write | exec tools, and safety patterns |
| `always-ask` | read | everything else |

Safety patterns are the destructive/network/sensitive rules in `src/security/policy.ts`.
They outrank an "always allow": allowing `run_command` is not the same as allowing
`rm -rf /`. With no one to ask (`--print`, pipes, CI), a prompt becomes a refusal with
the reason — the old hard-block behavior.

```bash
bun src/cli.ts --approval always-ask     # confirm every write/exec
bun src/cli.ts --yolo                    # never ask (unattended runs)
bun src/cli.ts --max-output 8000         # tighter per-call context budget
```

## Sessions: Resume And Continue

Sessions are append-only JSONL and can be read back. Truncated last lines (killed
mid-write) and tool calls whose results never landed are repaired on load.

```bash
bun src/cli.ts --sessions                # list recent sessions
bun src/cli.ts --continue                # pick up the most recent one
bun src/cli.ts --resume 2026-07-26T17-35 # id or id prefix, or a path
```

Inside the REPL, `/sessions` and `/resume <id>` do the same, loading the old history
into the current session (which keeps its own log).

## MCP Servers

Any stdio MCP server's tools can join the local registry — for reverse engineering the
obvious one is [`ida-pro-mcp`](https://github.com/mrexodia/ida-pro-mcp), which puts
decompilation, xrefs, and renaming in reach of the agent.

```json
{
  "mcpServers": {
    "ida": {
      "command": "python3",
      "args": ["-m", "ida_pro_mcp.server"],
      "timeoutMs": 120000
    }
  }
}
```

Tools appear as `mcp__<server>__<tool>` and go through the same approval gate and
output budget as the built-ins. A server that fails to start is reported at boot and
skipped, never fatal. `/mcp` shows the state of each one.

## Built-In Skills And Knowledge

Project-local skills live under `skills/*/SKILL.md`. They are loaded at startup,
summarized into the system prompt, exposed as tools, and usable directly:

```bash
bun src/cli.ts --workspace ./demos/reverse-lab
```

```text
/skills
/skill ctf-first-pass scan the demo artifact
/skill android-apk-frida inspect this APK and propose hooks
```

The local Frida/Android/Web reversing corpus can be indexed into
`knowledge/reverse-index.json`:

```bash
bun scripts/import-knowledge.ts
```

By default it imports from `~/frida/reverse-engineering` (and the legacy
`~/frida/reverse_engineering` path when present). Search it from the REPL or let
the model call `knowledge_search` / `knowledge_read`; `knowledge_search` returns
an agent-ready digest by default, and `raw: true` keeps the old hit-list shape:

```text
/know frida ssl pinning
/know wasm crypto hook
```

## HUD

A live HUD replaces the plain spinner during a run: the task list on the left, telemetry on
the right, the planner → executor chain and overall progress in the header.

```text
╭─ ⠹ 0xAF·RE ──────────────────────────────────────────────────────────╮
│ codex → claude                                   ▰▰▰▱▱▱▱▱ 40%  $0.71 │
│ ✔ triage: file/arch/packer   1.2s │ out ▁▂▅█▆▃▂▁ 4.1k                │
│ ✔ strings + entropy sweep    3.1s │ think 105  in 12k  cache 416k    │
│ ⠹ locate the check function 2m08s │ ◷ 1m34s                          │
│ ○ reproduce the flag path         │ ▸ nm -an ./chall                 │
│ ┊ the checker looks like sub_401a20; check xrefs before patching     │
╰──────────────────────────────────────────────────────────────────────╯
```

Per-step elapsed time, a token-throughput sparkline, and the route chain are all live. The
panel degrades on its own: below ~60 columns it folds to a single column, and when the
terminal is short it sheds reasoning lines, then collapses finished steps, then trims
telemetry — it never grows taller than the terminal.

The task list is fed from two places:

- the `codex` / `claude` CLI event streams — Codex `plan_update` / `todo_list`, and Claude
  `TaskCreate` / `TaskUpdate` (ids bound from `tool_use_result`), plus legacy `TodoWrite`;
- the host-side `update_plan` tool, used by the direct-API providers.

Every change is appended to the JSONL session, so a run's plan can be replayed afterwards.
`/plan` reprints the current one, and the final list is archived into the scrollback when a
turn ends. The HUD is purely observational — it does not drive routing.

Default policy:

- reads stay inside the workspace,
- writes are disabled unless `--write` is passed,
- network commands are disabled unless `--allow-network` is passed,
- secret-like paths are blocked unless `--allow-sensitive` is passed,
- destructive shell patterns are blocked.

## Architecture

```text
CLI / REPL
  -> config + provider registry
  -> AgentLoop
      -> provider.complete(system, messages, tools)
      -> assistant text/tool_calls
      -> tool registry execution
      -> toolResult appended
      -> continue until final
  -> JsonlSession append-only persistence
```

The provider layer currently supports:

- OpenAI Responses style (`codex`)
- Anthropic Messages (`claude`)
- xAI Grok through the OpenAI-compatible Responses API (`grok`)
- local Grok Build through `cli-tmux` (`grok-cli`)
- OpenAI-compatible Chat Completions (`deepseek`, `glm`)
- local `mock`

## Notes For 0xAF

This tool is scoped for authorized CTF/lab/local reverse engineering. It is designed to help with binary triage, static inspection, local dynamic experiments, solve planning, and reproducible notes.
