会展示过程的
逆向工程 Agent。

0xAF-Re 在终端里把 planner、executor 和 researcher 分开调度，配 34 个内置逆向/CTF 工具。 它能做 APK、ELF/PE/Mach-O 深度检查、反调试与壳识别、二进制 patch 差分、Web/WASM、Frida hook、radare2/JADX/Ghidra/Burp/mitmproxy/Unicorn/unidbg 工作流；有 GPT Cyber、Claude Code CVP、Grok 等更适配安全研究的 route 时体验更顺， 普通 provider 则可走 caveman 本地证据包。一个静态 Go 二进制，不需要 JS runtime。

$ go install github.com/overkazaf/re-agent/cmd/0xaf@v0.1.20
36 ms 启动 9 MB 二进制 34 工具 30 skills 8 provider 9 workflow 0 JS runtime

项目特点

为日常授权逆向里“模型太谨慎、过程不可见”的问题做改良。

0xAF-Re 源于作者日常 RE/CTF 工作里的痛点：CC 类 CLI 风控升级后，普通模型面对逆向语义也更容易过度谨慎，本地样本分析经常被打断。它不做隐写、暗语或绕策略，而是把任务限定在授权、本地、可审计范围内，再用多模型角色组合提升体验。

多模型组合

planner 负责路线，executor 负责工具，researcher 负责资料。三个角色可以接不同 provider 或具体模型，并可在运行中用 /planner、/executor、/researcher、/model 切换。

专用订阅加成

如果你有 GPT Cyber、Claude Code CVP、Grok 或类似更适配安全研究/逆向的 route，/workflow auto 可以走 specialist 路径，规划和工具推进会更顺。

普通模型也能跑

没有 specialist route 时，caveman 会把任务拆成 planner 全局视图和 executor 本地证据包。executor 只拿收窄后的只读工具，专注文件类型、字符串、熵、导入、符号和偏移等事实。

后续可评测

计划加入本地模型和具体评测样例：同一个 artifact、同一套 workflow、不同 provider，对比完成率、证据质量、耗时和人工修正量，用结果推动迭代。

任务先声明，再开工

/goal 把一句话目标变成钉死的契约：目标哈希与格式由宿主固定，build 通过、replay 一致、证据数量这些验收标准在 writeup 前对照账本逐条检查，过不了就写不了报告。

能力跟着任务走

声明生效时同时拉起任务级沙箱：网络与设备访问默认拒绝，/cap 运行中单项授权/收回，每条被闸门过的命令连同决策和来源进动作日志，任务结束授权一起过期。

结论要经得起复核

证据（ev_NNN）和假设（H-NNN）放在 transcript 之外的宿主状态里：矛盾让置信度减半并级联到派生结论，确定性仲裁器在每次工具结果后交叉核对，/audit 再把假设栈交给第二个模型做隔离会话的对抗复核。

Workflow

有专用订阅就直跑；没有就拆成本地证据包。

模式适合什么时候作用
off默认不改写你的 prompt
auto机器上可能有 GPT Cyber / CC CVP 路由能走 specialist 就走，否则走 caveman
specialist有授权 cyber/CVP 类 provider先规划，再调用 skills 和本地工具推进
caveman普通 providerplanner -> 隔离 executor，只传本地证据包
专用模式用途
research调研公开资料（Web / GitHub / arXiv），输出带出处报告
writeup只基于会话内已入库证据整理结构化分析报告
ctf围绕单一题目完成粗筛、规划、求解与精确 flag 验证
reverse交互式逆向：样本类型选择器 → 9 阶段推进 → 验证与审计硬闸门 → RE HUD → 证据账本
engineering接口与协议工程化还原：恢复数据结构、客户端 stub 与测试
 
/workflow auto
/workflow caveman
/workflow reverse
0xaf --workflow specialist -p "triage ./app.apk"

caveman 模式不是暗语、编码或绕策略。planner 看到完整授权任务；executor 开全新会话， 只拿本地 evidence packet 和收窄后的只读工具，用来收集文件类型、字符串、熵、导入/符号、 包结构、哈希、偏移和本地 blocker。

隔离本地证据流程具体做什么
1 · planner 阶段planner 看到完整授权任务，输出短计划和 EXECUTOR_PACKET
2 · 隔离 executorexecutor 开新的 provider session，只拿 packet、专用 system prompt 和收窄工具
3 · 证据工具executor 可 list/read/grep/hash，跑 strings/hexdump/entropy，检查符号、保护、carve 线索和 APK 结构
4 · 合并结果两段都写入同一个 transcript，最终返回 planner->executor 合并结果

auto 只是 resolver：检测到 cyber/CVP 标记就走 specialist， 否则走 caveman。真正的两段隔离执行只在 role 为 auto 且没有固定 provider 时触发；显式角色或强制 provider 会保持原语义，只套 workflow prompt。

它不绕过 provider 风控，也不隐藏会被标记的意图。实际效果是缩小合法上下文： planner 处理完整授权目标，executor 只收到工作区本地证据步骤，可调用工具保持只读， 两段过程都留在 transcript 里。

/workflow reverse 是最结构化的模式：样本类型选择器之后，按 9 个阶段推进 —— triage → static → dynamic → evidence → interface → hypothesis → verify → audit → writeup。每次完成的工具结果和假设状态都会写进 append-only 的 evidence-ledger.jsonl；阶段推进有硬闸门 —— 进入 audit 前必须先跑 verify_artifact，进入 writeup 前必须留下 audit 记录， 没有被验证过的结论到不了报告。账本之外还有三层宿主管的控制： /goal 钉死任务契约并对照证据检查验收标准， /cap 按任务闸网络与设备访问、动作全程留痕， /audit 在报告出来前把假设栈交给第二个模型做隔离复核。

桌面 GUI

基于同一套内核的 CRT 桌面工作台。

基于 Wails v2（Go 后端 + 原生系统 WebView）构建，直接复用同一个 core.AgentLoop、同一套 34 个内置工具、同一个 sessions/ 目录以及同一个任务能力沙箱，不是分叉实现。

远程模式

本地窗口规划，SSH 实验机执行。

通过 --remote <name> 或 /remote use <name> 将 run_command 与 !shell 自动路由到后台保活的 SSH 连接（30s keepalive + 默认 ssh -tt 远端 PTY）；模型也可显式调用 remote_exec 指定任意已保存主机。 凭据保存在 ~/.0xaf-re-agent/remote.json，使用绑定机器硬件标识的 AES-256-GCM 密钥本地加密。 

/remote add lab dev@10.0.0.5
/remote add srv root@srv.local --key ~/.ssh/id_ed25519
/remote use lab
!uname -a                                 shell escape -> ssh lab
0xaf --remote lab -p "inventory /opt"     启动即进入远程模式

安全与沙箱

任务能力沙箱在前，Tier × Mode 审批在后。

生效的 /goal 任务契约会先拉起任务级能力沙箱（/cap）：网络与设备访问默认拒绝，动作写入可审计日志。 通过沙箱后，再按工具风险等级与会话模式（safe / write / always-ask / yolo）执行审批；命中高危或网络特征的命令始终拦截询问。

上下文、压缩与恢复

磁盘转录完整保留，视觉快照无损压缩。

每次请求自动做两轮机械裁剪（折叠旧工具大输出、丢弃最旧对话轮次），严格保持 tool_use 与 toolResult 成对出现。 在 agent.config.json 中开启 "compactionStrategy": "snapcompact" 可将被裁剪历史本地确定性渲染为 PNG 快照帧，供支持视觉的模型直接读回偏移与地址细节；启动时还可用 --context "know:…" 或 --context "file:…" 注入参考资料。 

/context                               查看当前上下文预算占用
/compact                               将当前会话折叠为高密度简报
/sessions · /resume [id] · /new        列出历史、续接会话或开启新会话
0xaf --continue                        CLI 直接续接最近一次会话
0xaf --context "know:android packer"   注入本地知识库或文件上下文

安装

四条命令跑起来。

# 1. 安装固定版本
go install github.com/overkazaf/re-agent/cmd/0xaf@v0.1.20

# 2. 离线自检：不需要 key、网络或 CLI 登录
0xaf --smoke

# 3. 看当前 provider 登录状态
0xaf auth status

# 4. 打开工作区
0xaf --workspace ./ctf

默认复用本机 codex 和 claude CLI 登录；也可以改成 DeepSeek、GLM、Grok、OpenAI-compatible 或自建模型服务。

面向已获授权的 CTF、实验环境与本地逆向工作：二进制粗筛、静态分析、本地动态实验、solve 计划和可复现记录。
