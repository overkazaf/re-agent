TRUST ARCHITECTURE · 标准化 re-agent 信任架构

五道防线、七类档案与隔离审计，1:1 对齐工程治理规范。

当逆向 Agent 接入终端、反编译器、Frida、ADB、Unicorn/QEMU 与脚本重建能力，它就不再是代码解释器，而是高权限行动系统。 0xAF-Re 将 docs/WORKFLOW_STANDARD.md 中的标准化 re-agent 架构直接写进宿主 Go 代码与前端契约：权限可收束、事实与推断分离、假设可证伪可回滚、交付由执行与隔离审计裁定。

五道防线：逐一封堵逆向 Agent 典型失效路径

防线 01 · Capability Sandbox 防环境泄漏

能力沙箱：权限跟着动作走

/goal 生效即拉起任务级最小权限沙箱，network 与 device 默认拒绝，严防误读工作区外答案文件、宿主机凭据或未授权外联；任务结束或回滚时授权自动失效。

不变量：每条动作经 /cap 写入 Action State（命令 SHA-256、裁决、来源与绑定 hypothesisId）
防线 02 · Evidence Ledger 防样本投毒

证据账本 + UNTRUSTED DATA 隔离

所有工具原始观察由宿主写入 append-only 的 evidence-ledger.jsonl（ev_NNN），记录工具来源、视角（static/dynamic）与 SHA-256；样本内字符串与函数名强制打标 UNTRUSTED DATA，只作数据引用，永不进入指令层。

不变量：模型只能引用 ev_NNN，禁止伪造、覆盖或将自身总结当作输入事实
防线 03 · Hypothesis Manager 级联回滚

结构化假设管理器

拒绝把“这个常量就是 key”留在聊天里带着 Agent 空转。每条假设 H-NNN 在宿主侧维护 scope、falsifiers、next_test、dependsOn 与正反证据引用；反证命中即折半置信度并沿派生链级联触发 weakened / frozen / reevaluate。

不变量：状态迁移由宿主 hypothesis.Tracker 与确定性仲裁器执行
防线 04 · Execution Verifier 拦截单样本命中

执行验证器：candidate → verified

verify_artifact 强制区分 candidate 与 verified，执行构建、固定输入回放、边界/异常/失败样本与差分对比，记录 boundaryPassed、differentialCases 与 uncoveredPaths。

不变量：单样本偶然命中（total < 2）硬锁定为 candidate，严禁宣称算法已还原
防线 05 · Adversarial Auditor 三态裁决

隔离对抗审计：5 项强制核查

主 Agent 负责探索，绝不能自当裁判。/audit 启用独立隔离会话（Isolated=true、FreshSession=true、Tools=[]），只读契约、账本、候选结论与验证记录，逐条执行 5 项核查：直接证据、失败/边界覆盖、简化替代解释、越权核查、产物血缘。

输出三态裁决：accepted · rejected · needs_more_evidence

七类 Investigation State 任务档案

核心契约边界：Target State ≠ Objective State 严格分离。 Target State 的文件、架构、格式与 SHA-256 由宿主 goal.Sniff 只读锁定，禁止模型自填哈希；同一份二进制样本可以承载不同 Objective State（例如先做加壳识别，再做协议还原），从根源杜绝任务漂移与偷换目标。
档案域回答什么问题核心字段宿主治理规则
1. Target State 针对哪个样本的哪个版本？ file · sha256 · arch · format · version · scope 宿主 goal.Sniff 只读锚定，与 Objective 严格分离
2. Objective State 要证明什么、何时停止？ primary · deliverables · constraints · stopConditions · acceptance 模型起草、操作员 /goal accept 批准，Writeup 前逐条核验
3. Evidence State 工具真实观察到了什么？ ev_NNN · source · kind · view · sha256 · untrustedInput Append-only 不可变账本；不可信样本输出强隔离
4. Hypothesis State 有哪些竞争解释与反例？ H-NNN · claim · scope · falsifiers · nextTest · dependsOn 支持多解释并行竞争与冲突折半级联回滚
5. Action State 提议并执行了哪些高权限动作？ tool · capability · sha256 · decision · origin · hypothesisId 所有动态动作须绑定目标 hypothesisId 回答“验证哪条 nextTest”
6. Verification State 重建产物是否与原行为等价？ build · passed/total · candidate|verified · boundaryPassed · uncoveredPaths total < 2 或缺少边界/失败用例时锁定为 candidate
7. Audit State 独立读者是否发现缺口或越权？ verdict · checks[5] · auditorProvider · findings 任何回放失败或新矛盾即时退回 needs_more_evidence / rejected

运行态四角色控制面轮换

在 9 阶段 RE 工作流（TRI → STA → DYN → EVI → IFC → HYP → VER → AUD → WRI）的每个动作周期内，控制面按需在四个运行态角色之间轮换，而非僵化单向流水线：

Tool Router 按阶段分发工具 · 先过能力沙箱
⇄
Evidence Ledger 剥离不可信载荷 · 落盘 ev_NNN 与假设栈
⇄
Execution Verifier 构建 · 回放 · 边界差分 · 判定 verified
⇄
Adversarial Auditor 零历史零工具 · 5 项核查 · 三态裁决

五维可信度与成本指标（§7.5 Scoreboard）

把“报告写得顺滑”与“结论工程可信”彻底拆开量化，在仪表盘遥测与交付档案中持续可见：

evidence_coverage

证据覆盖率

最终活跃结论中可回溯至 Evidence Ledger 有效原始观察（ev_NNN）的比例。

replay_pass_rate

回放通过率

固定输入、边界输入与失败样本下重建产物的通过比例（passed / total）。

wrong_hypothesis_lifetime

错假寿命

错误假设从提出到被削弱、淘汰或级联回滚所消耗的轮次、证据步数与 token。

overreach_count

越权次数

范围外文件、网络、设备与凭据访问次数，明确区分“被沙箱拦截”与“越权成功”。

cost_per_accepted_finding

单结论成本

通过隔离审计验收的每条结论所分摊的模型 token、工具与设备总成本。

WRI [9/9] 硬交付闸门

7 项完成门禁（全部满足方可出报告）

  1. 1目标与范围可复现：Target State 与 Objective State 严格分离并已锁定。
  2. 2关键结论全部入账：每条结论均可回溯至 append-only 账本的 ev_NNN。
  3. 3主要假设经过检验：核心假设完成支持、反驳或清理，无悬空 reevaluate。
  4. 4产物通过多维验证：构建、回放、边界/失败与差分用例达标，状态为 verified。
  5. 5高风险动作全部留痕：所有动态与外部动作通过能力沙箱并落盘 ActionRecord。
  6. 6对抗审计无未解冲突：隔离审计 5 项核查全过，裁决为 accepted。
  7. 7明示边界与已知未知：报告显式列出 Known Unknowns、uncoveredPaths 与 nextTest。
HANDOVER READINESS

交接三问：跨轮次、跨模型、跨团队直接接手

任务收尾、崩溃续跑或移交同伴时，档案不靠口头回忆，必须直接回答三个工程问题：

  1. Q1结论来自哪一次运行？
    精确锚定 Session ID、evidence-ledger.jsonl 路径、ev_NNN 与产物 SHA-256。
  2. Q2换模型或换工具后能不能复现？
    交付独立可执行的 replay / differential 测试命令与固定输入向量，不绑定特定对话历史。
  3. Q3失败或偏差归因于哪一层？
    把根因清晰拆成模型推理 / 工具故障 / 运行环境 / 样本数据与投毒四层，避免盲目重试。

WORKFLOW MODES · 工作流与隔离取证

有专用安全路由就直跑；普通模型拆成本地证据包。

0xAF-Re 不做暗语、隐写或绕过策略，而是把任务严格收束在授权、本地、可审计范围内：拥有 GPT Cyber、Claude Code CVP、Grok 等安全研究友好路由时直走 specialist；使用普通 Provider 时，通过 caveman 将全局规划与只读本地取证隔离拆分，让普通模型也能稳定推进逆向流程。

路由模式适用场景执行方式

writeup严格限定仅基于当前会话已入账且通过验证的证据生成结构化报告

REMOTE SSH & MODEL SEATS · 远程实验机与四席位分工

本地指挥规划，SSH 实验机执行；四个模型席位各司其职。

/remote add lab dev@10.0.0.5
/remote add srv root@srv.local --key ~/.ssh/id_ed25519
/remote use lab

INSTALL & VERIFICATION · 安装部署与质量基线

四条命令跑起 CLI，一条命令构建 3D 桌面工作台。

# 1. 安装静态 Go 二进制（零 JS Runtime）
go install github.com/overkazaf/re-agent/cmd/0xaf@v0.1.20

# 2. 离线自检：无需 API Key、网络或 CLI 登录
0xaf --smoke

# 3. 检查当前 Provider 登录与路由状态
0xaf auth status

# 4. 进入授权逆向工作区
0xaf --workspace ./ctf
# 从 main 源码构建最新 3D 原生桌面工作台
git clone https://github.com/overkazaf/re-agent.git
cd re-agent

# 构建 Wails v2 原生桌面端，或直接起浏览器演示沙盒
make gui
make gui-demo

# 全量回归验证（Go 核心 + 前端 Vitest）
go test ./...
npm --prefix gui/frontend test
