standardized re-agent trust architecture

Five defenses between a plausible story and a verified finding.

Once an LLM touches a shell, decompiler, Frida, ADB, or Unicorn emulator, it becomes a high-privilege action system. 0xAF-Re implements the canonical re-agent governance standard 1:1 across Go core state, Wire DTOs, and GUI inspection surfaces so confidence never substitutes for replayable evidence.

Defense 01 Action State

Capability Sandbox

Failure mode: Blanket permissions read out-of-scope files, host credentials, or hit the network silently.

Task-scoped least-privilege grants (network / device deny-by-default) that expire immediately on task completion or rollback. Every intercepted call lands in Action State with tool, capability, command SHA-256, decision, origin, and bound hypothesisId.

Defense 02 UNTRUSTED DATA

Evidence Ledger + Untrusted Isolation

Failure mode: Model summaries masquerade as facts; adversarial symbol names poison the prompt layer.

Host-managed append-only evidence-ledger.jsonl assigns immutable ev_NNN IDs with tool source, static/dynamic view, artifact path, and SHA-256. Raw binary strings are tagged untrustedInput: true — citable as data, never executable as instructions.

Defense 03 Cascade Rollback

Hypothesis Manager

Failure mode: A wrong early assumption (“this constant is the AES key”) steers dozens of wasted turns.

Structured H-NNN records pin claim, scope, confidence, falsifiers, nextTest, and dependsOn. Contradictory evidence deterministically halves confidence and cascades weakened / frozen / reevaluate across derived nodes.

Defense 04 candidate → verified

Execution Verifier

Failure mode: Hardcoded solve scripts or single-sample coincidences claimed as recovered algorithms.

Strictly separates candidate from verified via verify_artifact: runs build, fixed-input replay, boundary/failure cases, and differential checks, recording boundaryPassed, differentialCases, and uncoveredPaths. Single-sample hits (total < 2) cannot promote.

Defense 05 Isolated · Tools=[]

Adversarial Auditor

Failure mode: The explorer grades its own homework, or spins indefinitely without a stop condition.

Runs in a fresh, tool-free context (Isolated=true, FreshSession=true, Tools=[]) reading only the scope declaration, ledger, and verification records. Evaluates 5 mandatory checks (direct_evidence, failure_edge_coverage, simpler_alternative, scope_overreach, artifact_lineage) and issues a tri-state verdict: accepted / rejected / needs_more_evidence.

7-State Investigation State Archive — Single source of truth across turns, models, and tools. Models read summaries; the host owns the full durable archive.

4 Rotating Runtime Roles & 9-Phase Gated Control Loop

Rather than a brittle linear chain, the runtime control plane rotates across four specialized roles on every action cycle, mapped onto the 9-phase RE HUD.

Tool Router ⇄ Evidence Ledger ⇄ Execution Verifier ⇄ Adversarial Auditor
Role 01

Tool Router

Dispatches static/dynamic tools based on Target State and phase; enforces Capability Sandbox pre-flight.

Role 02

Evidence Ledger

Isolates untrustedInput payloads, persists immutable ev_NNN, and drives hypothesis state transitions.

Role 03

Execution Verifier

Runs build, fixed replay, boundary/failure inputs, and differential checks to arbitrate candidate vs verified.

Role 04

Adversarial Auditor

Evaluates 5 checks in a zero-history, zero-tool session and signs accepted / needs_more_evidence / rejected.

Separating smooth prose from verifiable engineering quality across every investigation.

Pass ratio (passed / total) across fixed vectors, boundary cases, and failure inputs.

Turns, evidence steps, and tokens spent between proposing a wrong claim and weakening or pruning it.

Cost / Accepted Finding

Total token, tool, and lab spend (USD) amortized per auditor-accepted conclusion.

7 Completion Gates (WRI [9/9])

Every gate must pass before a session unlocks final writeup delivery.

  1. 1Reproducible Target & Scope: Target State (hash/arch/format) and Objective State separated and pinned.
  2. 2All Findings Ledger-Backed: Every key conclusion cites immutable ev_NNN observations.
  3. 3Hypotheses Resolved: Major hypotheses verified, falsified, or cascaded clean — zero dangling reevaluate.
  4. 4Multi-Dimensional Verification: Build, fixed replay, boundary/failure, and differential checks reach verified.
  5. 5High-Risk Actions Audited: Every dynamic/external action passed Capability Sandbox with an ActionRecord.
  6. 6Adversarial Audit Accepted: All 5 isolated audit checks pass with verdict = accepted.
  7. 7Explicit Known Unknowns: Report names uncoveredPaths, scope limits, and concrete nextTest steps.

3 Handover Questions

Every archived investigation must answer these immediately for teammates or resume runs:

01 · Which exact run produced this conclusion?

Pinned to Session ID, evidence-ledger.jsonl path, ev_NNN IDs, and artifact SHA-256.

02 · Can another model or tool reproduce it?

Ships standalone replay and differential test commands with deterministic fixed input vectors.

03 · Which layer caused any failure or drift?

Explicitly separates model reasoning, tool failure, runtime environment, and sample data / poisoning.

why it is built this way

Built after ordinary coding agents got less useful for RE.

The project started from daily authorized RE/CTF work where CLI risk controls tightened and general models became overly cautious around reverse-engineering language. 0xAF-Re does not hide intent. It keeps work local, authorized, and auditable, then composes models so each seat handles the job it excels at.

Four-Seat Model Composition

A planner reasons about the target, an executor drives local tools, a researcher gathers prior art, and an isolated auditor challenges conclusions. Switch live with /planner, /executor, /researcher, and /model.

Specialist When Available

If you have GPT Cyber, Claude Code CVP, Grok, or a similar route tuned for security research, /workflow auto takes the specialist path and keeps planning plus tool work in one smooth loop.

Caveman for Ordinary Models

Without a specialist route, caveman mode splits the task into a full planner view and a narrow executor packet. The executor sees local evidence requests, not the whole objective, and uses a read-only toolset for file facts.

One Static Binary

Prompts and 30 RE skills are embedded via embed.go. make cross builds linux/darwin × amd64/arm64 (~9 MB, 36 ms start). Lab boxes rarely have a JS runtime, and you should not need one to triage a binary.

Cancellation That Lands

^C cancels the HTTP request, kills the tmux session, and signals tool subprocesses in their own process group. No orphaned objdump chewing a core after you walked away.

Contained by Default

Reads stay inside the workspace. Writes stay off until --write. Network and credential-shaped commands stop and ask. Destructive shell forms are refused.

Stdio MCP Bridge (IDA Pro & Friends)

Any stdio MCP server joins the same tool registry, capability sandbox, approval gate, and output budget. Drop ida-pro-mcp into agent.config.json to bring decompilation, xrefs, and renaming straight into the loop: 

{ "mcpServers": { "ida": {
    "command": "python3",
    "args": ["-m", "ida_pro_mcp.server"],
    "timeoutMs": 120000
} } }

Exposed as mcp__ida__<tool>; failed servers are reported at boot and skipped non-fatally. Check state anytime with /mcp.

safety & approval matrix

Capability sandbox first. Tier × mode second. Safety patterns outrank both.

An accepted /goal arms the task-scoped capability sandbox (/cap) with network and device access denied by default and every gated call logged. Calls that clear the sandbox then meet Tier × Mode approval — and commands matching destructive, credential, or network patterns always ask.

context budget, snapcompact & resume

Full transcript on disk. Precision budget upstream.

One raw objdump -d can sink an ordinary coding agent. 0xAF-Re trims upstream context in two mechanical passes (eliding old tool bodies first, then dropping oldest exchanges while keeping tool_use/toolResult pairs intact). Enable "compactionStrategy": "snapcompact" in agent.config.json to render dropped exchanges into deterministic local PNG snapshot frames so vision-capable models retain hex offsets and addresses. 

/context   ≈12400 tokens of 48000 budget (25%) · 42 messages
/compact   fold session into a high-density briefing and free context
/sessions · /resume [id] · /new
0xaf --continue
0xaf --context "know:android packer"   seed local knowledge or file:… notes up front

Append-only JSONL sessions repair truncated final lines and orphan tool calls automatically on resume.
